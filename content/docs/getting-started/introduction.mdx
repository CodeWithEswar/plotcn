Plotcn is a source-first visualization system for React.

It brings together **Recharts**, **D3.js**, and **Google Charts** under a shared developer experience while keeping the strengths of each engine available. Instead of hiding visualization code behind a rigid package boundary, Plotcn distributes components through the **shadcn Registry** so the implementation can live directly inside your application.

<VisualizationSystemPreview />

## What is Plotcn?

Plotcn is a collection of reusable, production-oriented visualization components designed for modern React applications.

Instead of asking your application to depend on a monolithic abstraction layer, Plotcn provides the component source itself. Install a visualization, inspect the generated file, adapt the interaction, replace the data model, adjust the visual tokens, or rebuild parts of it entirely.

<DocsCallout title="Source first">
Plotcn treats customization as part of the normal workflow, not an escape hatch. Components are meant to live in your application, not behind an opaque package boundary.
</DocsCallout>

## Why Plotcn exists

Visualization libraries already solve the fundamental problem of drawing charts extremely well.

The difficult part in a real product often lives around the chart: responsive containers, loading and empty states, accessibility summaries, tooltips, legends, theme integration, interaction behavior, motion, error handling, and visual consistency across an application.

Plotcn focuses on this product layer while preserving access to the engine underneath.

## Three engines, one visual language

<EngineGrid />

### Recharts

Use Recharts when you want a declarative React model for common product and dashboard visualizations. It is a strong default for line, area, bar, radial, categorical, and other familiar chart patterns.

Plotcn adds production-ready composition, styling, responsiveness, accessibility patterns, and source-distributed components around that model.

### D3.js

Use D3.js when the visualization itself needs deeper mathematical and geometric control.

D3 is particularly useful when custom layout, coordinate calculations, hierarchy, force networks, geographic projection, brushing, zooming, or specialized interaction are central to the experience. Plotcn uses D3 primarily for calculation and geometry primitives while React remains responsible for component lifecycle and DOM rendering where appropriate.

### Google Charts

Use Google Charts when a Google-provided visualization fits the problem well, especially when working with **GeoChart** for worldwide and regional choropleth maps or mature standard chart types.

Plotcn provides the React integration, lifecycle handling, singleton script loading, responsive shell, theme adaptation, loading and error states, and documentation around the Google runtime.

<DocsCallout title="External runtime">
Google Charts relies on Google's hosted visualization runtime. For Google Charts components, you own the Plotcn React wrapper and shell code within your application, while the underlying chart rendering engine is loaded from Google.
</DocsCallout>

### Engine Comparison

| Capability | Recharts | D3.js | Google Charts |
| --- | --- | --- | --- |
| Dashboard charts | Excellent | Capable | Strong |
| Custom geometry & math | Limited | Excellent | Limited |
| React-first composition | Native | Plotcn-managed | Plotcn-managed |
| Geographic choropleths | Limited | Strong with geo modules | Excellent via GeoChart |
| External runtime dependency | No (bundled) | No (bundled) | Yes (Google hosted) |
| Source-level customization | Full component | Full component | Wrapper & shell |

## Install the source. Keep the source.

Plotcn follows a source-distribution model.

A component is discovered in Plotcn, installed through the shadcn Registry, and written into your own project. From that point forward, it becomes part of your application source tree.

<RegistryFlow />

This changes the relationship between your application and the component. You are not limited to a configuration surface chosen by an external author. You can open the file and change the implementation itself.

## One visual language across different engines

Plotcn does not try to make Recharts, D3.js, and Google Charts pretend to be the same visualization library.

Their rendering models, capabilities, and APIs are fundamentally different — and those differences are useful.

Instead, Plotcn standardizes the product-level experience around them:

- Responsive containers and resize observers
- Semantic theme tokens and dark-mode adaptation
- Loading, empty, and error fallback states
- Accessibility labels and hidden screen-reader summaries
- Tooltip and legend presentation patterns
- Motion conventions respecting reduced-motion preferences
- Clear documentation and clean component source organization

<DocsCallout title="Shared experience, not a universal wrapper">
The goal is consistency around the visualization without removing the capabilities that make each engine valuable.
</DocsCallout>

## How Plotcn is structured

<PlotcnArchitecture />

Plotcn keeps engine-specific implementation separate from the shared chart layer.

This prevents a Google Chart from depending on D3 internals, or a D3 visualization from being constrained by a Recharts-style API. Shared infrastructure is used only where the concern is genuinely common: theme variables, container bounding, state fallbacks, and accessibility primitives.

## Choose the right engine

### Choose Recharts when

- You are building dashboards or familiar application charts
- You want a declarative React component API
- You want to move quickly with standard Cartesian patterns
- The chart fits common line, bar, area, scatter, or radial structures

### Choose D3.js when

- The visualization requires custom geometry, scales, or layouts
- Interaction, brushing, or zooming is central to the product experience
- You need hierarchy, force-directed networks, voronoi, or advanced projections
- You want maximum control over the visualization pipeline

### Choose Google Charts when

- A Google chart type already matches your requirement
- You need choropleth maps via **GeoChart**
- You prefer Google's mature chart runtime
- An external hosted runtime is acceptable for your deployment environment

## What Plotcn is not

Plotcn is intentionally not trying to become a wrapper around every chart library on npm.

A visualization or engine should only become part of Plotcn when the project can add meaningful value through better defaults, source ownership, responsiveness, accessibility, integration, documentation, or developer experience.

Plotcn is also not a no-code chart builder. The source code is intentionally visible and accessible because developers are expected to own and evolve it with their application.

## Project status

Plotcn is being built incrementally.

The documentation system and registry foundation are established first. Visualization components are then implemented, tested, documented, and published one by one.

This keeps the public catalog aligned with functionality that actually works instead of filling the project with placeholder components.
